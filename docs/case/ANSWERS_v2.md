## 1. `state_accuracy` и привязка к объекту — признано, исправлено

Кандидаты теперь отбираются по паре «объект + атрибут»: имя объекта сравнивается
нечётко (стемы, порог 0.80 для коротких имён), объект-клиент у тарифа/действия
пропускается. `object.id` по-прежнему не требуется (schema этого и не обещала) —
сопоставление по имени. Ваш минимальный пример теперь даёт 1.0; на всём val
эталон против себя: `state_accuracy = 0.9984` (единственный промах — объект
с техническим именем-идентификатором в одном звонке, 1 из 623).

## 2. Даты — семантика объявлена, метрика исправлена

Официальные правила (внесены в `schema.md`):

- `valid_from` — момент действия/состояния в прошлом или срок в будущем
  (для договорённостей). Если срок в тексте не назван, возвращайте дату звонка
  (`started_at`) — такие факты темпорально не проверяются.
- `temporal_recall` с v2 считается **только для фактов, чья дата восстановима
  из транскрипта**: оценщик содержит банк относительных выражений корпуса
  («вчера», «со вторника», «на прошлой неделе», «через три дня», «в четверг»…)
  и сверяет дату эталона с восстановимыми датами звонка. Оба ваших примера
  (действие «оплатила вчера» с датой звонка; симптом с непроизносимой датой
  3 мая) выпадают из темпоральной проверки — наказания за них больше нет.
- `action` исключён из темпоральной метрики: кейс определяет темпоральность
  для изменений состояния, тарифов, статусов заявок и сроков договорённостей.
- Скрытый тест-срез оценивается тем же правилом.

## 3. Каталог — справочник, а не закрытый алфавит значений

- Возвращать можно как каноническое значение из каталога, так и формулировку
  из текста: сравнение **симметрично нормализует обе стороны к каталогу**
  (порог снапа 0.85), а вложение короткой стороны в более длинную формулировку —
  совпадение. Ваш пример: «Орбита-Люкс» против «тариф Орбита-Люкс» теперь
  засчитывается (проверьте `match_facts` — 1 пара).
- Для свободных формулировок (договорённости, действия) действует нечёткое
  сравнение по опорным словам: покрытие ≥0.7 shorter-side при совпадении
  атрибута, полярности и объекта.

## 4. Сопоставление объектов — признано, исправлено

В выданной вам копии оценщика был артефакт посимвольного сравнения имён и
лазейка нулевого сходствия. В v2 имя сравнивается целиком, нулевое сходствие
бракует пару. Ваши примеры «Роутер vs Телевизор/Репитер» — 0 совпадений.

## Доп. расхождение baseline — объяснено и закрыто

Причина: в папку попала устаревшая копия `case_metrics.py`, а сохранённые
метрики были посчитаны промежуточной версией оценщика на прежнем val. С v2
версия скрипта прошита в код и в вывод (`metrics_version: 2.0`).

**Официальные метрики базового экстрактора (glm-5.3, zero-shot, val, оценщик v2):**

| метрика | значение |
|---|---|
| fact_precision / fact_recall | **0.3515 / 0.3995** |
| temporal_recall | **0.5000** (n=396) |
| state_accuracy | **0.5169** (n=623) |
| grounding_turn | **0.7123** |

Критерий «падение относительно базы ≤ 0.02» считается по этим числам и этой
версии оценщика, одинаково на val и скрытом тесте. Самопроверка эталона
(`val.jsonl` против себя): precision/recall/temporal/grounding = 1.0,
state_accuracy = 0.9984.
